INTERVIEW BRIEF
Read before changing code
You are reviewing a small Python service that limits requests per user. The intended policy is a rolling window: each user may make at most N accepted requests during the previous W seconds. A request exactly W seconds after an earlier accepted request is outside that window. Rejected requests must not extend the user's lockout.

The current implementation is failing in production around burst traffic and window boundaries. Find the behavioral defects, explain your reasoning, and submit a corrected single Python file.

Interface: RateLimiter(max_requests, window_seconds) and allow(user_id, now) -> bool. now is a numeric timestamp provided by the caller. Different users have independent limits. Preserve the public interface and avoid external dependencies.
